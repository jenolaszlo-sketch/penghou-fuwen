**Assessment:** The compiler, immutable definition boundary, exact catalogue pins, and separation of workflow decisions from inference mechanics are sound foundations. Complex inference has a useful deterministic vertical slice, but its current identity, budget, recovery, and persistence behavior does not yet meet its stated contracts. Close those gaps before expanding supported effects or presenting the protocol as production ready.

## Confirmed defects

### 1. P1 — Distinct inference invocations share operation identities

[FuwenInferenceCoordinator.cs:279](../src/Penghou.Fuwen.Zhinu/FuwenInferenceCoordinator.cs:279)

`Prepare` hashes structural/runtime paths, profile name/version, prompt definition digest, and tool names/versions. It omits the workflow run, execution fingerprint, effective prompt values, context snapshot/value identities, descriptor content digests, and step revision. The `executionFingerprint` argument supplied to `ExecuteAsync` is unused.

**Reproduction:** Execute the same registered workflow twice with different input strings. Both complete, but their observed `InteractionId` values are identical. Consequently their model operation IDs also collide, and tool operation keys collide when ordinals and provider call IDs match.

Zhinu's run-scoped storage can still keep its own rows separate; the problem is the identity exported to provider/tool adapters and evidence sinks. An adapter implementing deduplication using that identity can return an earlier request's result. Correlation also merges unrelated executions.

**Fix:** Derive identity from an explicit invocation contract: run identity, structural/runtime path, revision, execution fingerprint, and normalized effective request fingerprint. Preserve it across recovery of that invocation. Hash exact descriptor identities and bound input/context values. Define fork/restart identity rules explicitly.

### 2. P1 — A final answer bypasses aggregate budget validation

[FuwenInferenceCoordinator.cs:763](../src/Penghou.Fuwen.Zhinu/FuwenInferenceCoordinator.cs:763), [final-candidate branch:801](../src/Penghou.Fuwen.Zhinu/FuwenInferenceCoordinator.cs:801), [remaining limits:1160](../src/Penghou.Fuwen.Zhinu/FuwenInferenceCoordinator.cs:1160)

Usage is accumulated, then a final candidate is schema-validated and accepted. Aggregate checks only run before another loop operation, so there is no check after the final paid call. The coordinator also lacks the conservative pre-operation reservations described by ADR 0011: checking that prior spend is below the ceiling does not establish that the next call fits. `RemainingLimits` does not pass a cost allowance to the turn executor.

**Reproductions:** A total-token ceiling of 1 accepts a final turn reporting 20 tokens; the same ceiling accepts unknown final usage; a USD ceiling of 1 microunit accepts a final turn costing 500 microunits. All runs finish `Completed`.

**Fix:** Reserve a provable upper bound before external work, settle from durable usage, and validate final totals before success. Keep exact-bound success distinct from permission to start another call. Unknown usage needs a retained reservation or a normalized failure. Post-call rejection alone cannot undo overspend.

### 3. P1 — Currency enforcement ignores the declared currency

[FuwenInferenceCoordinator.cs:1119](../src/Penghou.Fuwen.Zhinu/FuwenInferenceCoordinator.cs:1119)

`AccumulateUsage` ignores its `effective` argument. It compares a new cost currency with previous reported currencies, but never compares it with `effective.Cost.Currency`. The first reported currency therefore becomes authoritative even when the source budget names a different currency.

**Reproduction:** A USD-bounded workflow receives EUR usage on its first model turn, executes the requested tool, and starts another model turn. It should stop before additional work because the USD allowance cannot be reconciled with that evidence.

**Fix:** Validate every priced operation against the admitted currency and pricing policy before settling or authorizing another operation. Give host-only monetary limits an explicit currency/provenance contract as well.

### 4. P1 — Raw tool payloads are persisted in ordinary workflow storage

[FuwenInferenceCoordinator.cs:1025](../src/Penghou.Fuwen.Zhinu/FuwenInferenceCoordinator.cs:1025), [conversation retention:1078](../src/Penghou.Fuwen.Zhinu/FuwenInferenceCoordinator.cs:1078)

Tool step results contain raw output JSON. That JSON is also appended to the conversation serialized into loop state. Initial rendered prompts/context and final candidates are similarly serialized. The core defines `ProtectedPayloadReference`, but the coordinator does not use it or expose a protected-payload storage port.

**Reproduction:** Return a unique private marker from a tool, finish the workflow, close the engine, and inspect the SQLite database. The raw marker is present. It did not originate in workflow input or the final answer.

This contradicts ADR 0010 and the CI-5 claim that sensitive payloads live behind host-controlled references. A sanitized optional evidence sink does not sanitize the authoritative journal. This is a retention/access-boundary issue, not evidence of external disclosure.

**Fix:** Introduce a host-owned protected payload store/resolver. Persist immutable references, digests, sizes, and retention policy in ordinary history; load authorized content for continuation. If raw durable transcripts are intentional, state that as the actual contract and expose explicit retention/access controls.

### 5. P1 — Coordinated execution can pass another executor's preflight

[FuwenZhinuWorkflowFactory.cs:451](../src/Penghou.Fuwen.Zhinu/FuwenZhinuWorkflowFactory.cs:451)

When coordinated execution is selected but the configured turn executor does not implement `IInferenceTurnExecutorManifest`, registration falls back to the one-call executor's manifest/preflight. That executor will not perform the coordinated model calls.

**Reproduction:** Supply an unmanifested turn executor and the existing fixture's preflight-capable one-call executor. Registration succeeds. No capability check has established what the actual turn executor supports.

The constructed requirement also leaves recovery quality at `Unsupported`, does not request structured-output capability, and excludes the effective host ceilings. A report can therefore be successful without proving the requirements of the selected path.

**Fix:** Make preflight mandatory on the selected execution strategy. Construct requirements from the effective admitted execution contract, including host ceilings and required recovery behavior. Bind the selected implementation/runtime revision to registration identity rather than relying solely on catalogue identity.

### 6. P2 — The retained-evidence byte limit is accepted but unused

[FuwenInferenceCoordinator.cs:358](../src/Penghou.Fuwen.Zhinu/FuwenInferenceCoordinator.cs:358), [evidence construction:125](../src/Penghou.Fuwen.Zhinu/FuwenInferenceCoordinator.cs:125)

`MaxRetainedEvidenceBytes` is parsed, fingerprinted, minimized with host limits, and reported in effective limits. No coordinator code checks retained evidence bytes against it. Fixed maximum operation counts are a different bound.

**Reproduction:** A one-byte retained-evidence allowance is admitted and completes while recording normal operation and validation evidence.

**Fix:** Define exactly what the byte allowance includes and enforce it before persistence, with explicit bounded truncation or failure. Reject unsupported limits during preflight until enforcement exists. Also reconcile the API documentation's aggregate tool-byte wording with the current per-call argument/result checks.

### 7. P2 — Valid tool-call IDs become invalid operation keys

[InferenceTurn.cs:52](../src/Penghou.Fuwen/InferenceTurn.cs:52), [InferenceConformance.cs:296](../src/Penghou.Fuwen/InferenceConformance.cs:296), [InferenceReadTool.cs:32](../src/Penghou.Fuwen/InferenceReadTool.cs:32)

A provider call ID may be 256 UTF-8 bytes. The coordinator prepends the interaction ID and tool ordinal, then passes the concatenation to an operation-key constructor also capped at 256 bytes.

**Reproduction:** An otherwise valid 200-byte ASCII call ID is accepted as a proposal but causes the workflow to fail before tool execution.

**Fix:** Use a fixed-size digest for the operation key and retain the original call ID as separate bounded metadata. Check composition bounds, not just the bounds of individual fields.

## Additional code-reviewed risks and design gaps

**Ambiguous paid calls can be reissued after interruption.** [Model step execution](../src/Penghou.Fuwen.Zhinu/FuwenInferenceCoordinator.cs:654) invokes `ExecuteTurnAsync` directly. There is no provider receipt, durable submission handle, or reconciliation port. The existing [crash test](../tests/Penghou.Fuwen.Zhinu.Tests/FuwenInferenceCoordinatorTests.Matrix.cs:506) explicitly expects two executor calls after interrupting the first. Completed steps are reused, but a lost response after a remote provider accepted work can lead to another paid request. Reusing a string identity only prevents that if the adapter/provider actually guarantees deduplication; registration currently does not require that guarantee. Specify an explicit submit/receipt/reconcile or idempotent-execute contract, otherwise stop on an ambiguous durable claim. This risk was established from source and the existing fake recovery scenario, not a real paid-provider experiment.

**The turn request cannot describe a general admitted inference.** [InferenceTurnRequest](../src/Penghou.Fuwen/InferenceTurn.cs:112) has conversation, tool descriptors, and limits, but no profile descriptor, output type/schema, invocation authority, or context provenance. A shared executor cannot reliably route two profiles or request two different output schemas from this object alone. Passing an opaque interaction hash does not solve that. Carry a detached admitted inference contract or select an immutable descriptor-bound session before executing turns.

**Tool validation checks JSON shape, not the callable signature.** [ValidateProposals](../src/Penghou.Fuwen/InferenceTurn.cs:256) checks exact descriptor membership, read-only effect, duplicate IDs, byte size, and JSON-object shape. It does not validate required arguments or field types against the trusted `CallableContract`; tool output likewise lacks coordinator-side descriptor-schema validation. Hosts can implement those checks, but the framework's typed-tool guarantee then depends on every host doing so. Carry the admitted signature/schema to a shared validator, or clearly document and test that obligation at the execution port. `ScopeFor(tool)` returning only `name@version` is also not an actual resource grant; keep resource authorization explicit.

**Normalized model failures have no result case.** [InferenceTurnResult](../src/Penghou.Fuwen/InferenceTurn.cs:173) is a closed hierarchy with only a final candidate and tool calls. An adapter cannot return a typed refusal, rate limit, known pre-submission failure, or ambiguous receipt. Throwing most exceptions is mapped to `AmbiguousOperation`, even when the adapter knows no request was sent. Add explicit failure/ambiguity outcomes with commitment status and bounded evidence.

**Evidence reports recovery inaccurately.** [BuildEvidence](../src/Penghou.Fuwen.Zhinu/FuwenInferenceCoordinator.cs:170) reports either `Ambiguous` or `Fresh`. It never emits `Replayed`/`Reconciled`; operation summaries never record `Reused`. Operator-facing types promise distinctions the coordinator does not populate. Obtain execution-versus-reuse disposition from the durable boundary and persist it. Timeout and cancellation paths also need deliberate evidence handling; they can exit before the terminal sink call.

**Conversation limits do not compose.** [TryAppendMessage](../src/Penghou.Fuwen.Zhinu/FuwenInferenceCoordinator.cs:1104) checks total text bytes only, while turn constructors impose 64 messages and 65,536 bytes per message. A tool result permitted by the declared 262,144-byte result allowance can fail while constructing the next turn. These construction failures occur outside the model-call exception normalization. Enforce every effective boundary at append/preflight time and return a typed payload failure. Do not silently truncate tool results.

## OOP and implementation assessment

The core uses object-oriented boundaries appropriately: execution ports isolate infrastructure, sealed runtime values snapshot inputs, and the immutable definition store is stronger than merely calling a record immutable. Keep those decisions. A data-oriented IR with external visitors/switches is also reasonable; executable methods on every AST node would couple the IR to runtime concerns.

The main cohesion problem is that the roughly 1,200-line static inference coordinator owns identity construction, prompt/context rendering, protocol state, budget accounting, provider dispatch, JSON persistence, output validation, and evidence. Its mutable `CoordinatorState` permits combinations such as a string phase with inconsistent pending/output fields. Several findings come directly from invariants crossing those responsibilities.

Refactor along concrete contracts, not through a generic plugin framework:

1. An invocation identity factory shared with ordinary execution.
2. An effective-budget ledger with reserve/settle/finalize operations.
3. A durable operation boundary exposing claim, execution/reuse, and ambiguity.
4. A pure protocol transition component with explicit model/tool/terminal states.
5. A payload/evidence persistence component enforcing retention rules.

Keep interfaces at provider/storage/policy boundaries; internal deterministic helpers do not each need an interface. Move deterministic fakes and public conformance helpers into a testing package when the public API stabilizes. Production identity/scope generation currently depending on `InferenceTurnToolConformance` is the wrong dependency direction.

The separate one-call and coordinated paths duplicate request construction, validation, evidence, and recovery policy. Preserve modality-specific adapters where useful, but converge their shared semantics on one admitted contract; a one-turn execution should not have unrelated authority or evidence rules. Replace the growing positional `FuwenZhinuExecutionPorts` constructor with cohesive configuration that validates supported combinations. Hosts should not need an unused one-call executor to configure an exclusively coordinated workflow.

The compiler/source files are large and repeatedly traverse node variants. That is a maintenance concern, not itself a correctness defect. Introduce shared traversal only where repeated omissions justify it; avoid a broad visitor or inheritance rewrite while runtime contracts are still moving.

## Missed opportunities for usefulness and usability

**First, make the advertised path usable with an actual provider.** The stock [BaizeInferenceExecutor](../src/Penghou.Fuwen.Baize/BaizeInferenceExecutor.cs:340) does not implement `IInferenceTurnExecutor`; `BaizeOneTurnMapper` only maps response tool calls. A host still has to build the provider-facing multi-turn adapter. Ship one with exact routing, native assistant tool-call messages, typed output contracts, normalized failures, usage, and proven recovery behavior. Deterministic fakes are valuable, but cannot expose provider message-shape and deduplication limitations.

**Make failures usable by the authored workflow.** The design promises explicit review/replan/escalation, yet coordinator failures throw and the DSL has no general typed failure branch. Add a deliberate `Outcome<T>`/failure-binding design so a workflow can checkpoint after exhaustion, choose a bounded fallback, or ask for a decision. Keep semantic rework visible; bounded representation repair can remain inside inference. Do not finalize syntax before its IR, admission, formatter, and recovery semantics agree.

**Expose inspect/resume as a supported host experience.** An optional sink is not a complete durable query API. Offer a safe activity timeline: effective bounds, consumed/reserved budget, exact tools, current operation, replay status, final validation, and any operator action required. Provide explicit resume/reconcile/restart actions with their identity consequences. Keep payload viewing separately authorized.

**Add a small credential-free reference host or CLI.** A user should be able to compile, explain, check readiness, run a deterministic example, interrupt it, resume, and inspect evidence through one documented sequence. Show authored-versus-host bounds and unsupported combinations before execution. The package-consumer tests are useful verification, but are harder to discover and operate than a sample product surface.

**Prioritize composition based on real workflows.** Coordinated inference inside fan-out is deliberately rejected, which blocks common per-file review and per-document research use cases. Treat item-scoped durable coordination as a valuable next capability after correctness. Reusable bounded subworkflows/templates could later expose review/rework patterns without duplicating source. Keep externally meaningful writes as explicit activities; the deferred write-tool gate is a sensible boundary.

The uncommitted V2 roadmap additions already point toward typed evaluation outcomes, candidate comparison, and evidence-informed proposals. Those are useful directions, not newly discovered omissions. In particular, V2.2's two-candidate fixture would make a good composition acceptance test after operation identities and budget accounting are corrected. Distinguish a successful execution whose artifact is rejected from an execution failure; both need typed handling, but they should not share runtime status semantics.

**Reconcile documentation with executable capability tests.** README still describes IR v2–v8 although `FuwenContracts.IrVersion` is `fuwen-ir/v1`. The complex-activities overview says “not yet implemented”; its implementation plan marks CI-0–CI-7 complete; the capability matrix simultaneously says the durable tool loop is not implemented and supported. The graduation document is more candid about missing live-provider evidence, fan-out support, and evidence read-back. Maintain one capability table with links to concrete conformance cases, and require matching evidence before checking a milestone complete.

## Suggested order

1. Fix invocation identity, selected-executor preflight, aggregate budgets/currency, and payload persistence.
2. Establish an explicit ambiguous-operation recovery contract and truthful recovery evidence.
3. Complete the turn request/result model, schema validation, and composable byte/count bounds.
4. Build the real Baize turn adapter and reference host with provider fixtures.
5. Add workflow-visible failure handling, durable inspection, and item-scoped composition.

The biggest opportunity is to make one complex inference reliably bounded, inspectable, and resumable end to end. A generic “complex action” abstraction can wait until a second real protocol demonstrates what should be shared.
